# Слайди кейсів

Слайди згенеровані у фірмовому стилі на основі презентацій та фінмоделей
реальних кейсів (HTML → PNG, 1280×800 @2x).

- `case-1-cover.png`, `case-2-koshtorys.png`, `case-3-finmodel.png` —
  кейс «Майстерня БпЛА» (сторінка `/case-bpla`).
- `salon-1-cover.png`, `salon-2-koshtorys.png`, `salon-3-finmodel.png` —
  кейс «Салон краси повного циклу» (сторінка `/case-salon-krasy`).
- `ripak-1-cover.png`, `ripak-2-koshtorys.png`, `ripak-3-finmodel.png` —
  кейс «Вирощування озимого ріпаку на 30 га» (сторінка `/case-ripak`).
  Джерельний документ мав плейсхолдери `[ПІБ]`/`[П]` замість даних
  заявника (типова передача клієнтського файлу без персональних даних),
  клієнт підтвердив — це реальний кейс, грант отримано, як і два вище.
- `sto-cover.webp` — згенерований слайд у тому ж фірмовому стилі, що й три
  кейси вище (тизер на головній має лишатись однорідним рядом). `sto-1-photo.webp`,
  `sto-2-photo.webp`, `sto-3-photo.webp` — РЕАЛЬНІ фото приміщення заявника
  (не фотосток), використані у галереї на сторінці `/case-sto` — там доречно
  показати саме реальне приміщення, на головній — ні. Грант отримано (клієнт
  підтвердив) — сторінка водночас показує, що аудит знайшов до подання:
  кошторис перевищував ліміт і бракувало компресора.

Список кейсів для тизера на головній — `src/data/cases.ts`.

Замінити на реальні скрини презентації/плану можна, зберігши ті самі
імена файлів (співвідношення 1280×800). Фото юриста та фінансистки —
окремо у `src/components/Author.astro` і `FinancePartner.astro`.
