# GrantPlan: учёт обращений, денег и времени

Локальная книга Excel для владельца. Это следующий рабочий блок глобального плана: измерять обращения, подтверждённые поступления и труд. Сайт, Telegram и банковский кабинет с книгой не синхронизированы. Ввод ручной. Книга не отправляет сообщения, не запускает рекламу и не делает API-запросов.

## Работа с книгой

1. В «Обращения» внесите постоянный ID, дату первого контакта, источник и `REAL` либо `TEST`. Источник без доказательства — «Неизвестно», а не Direct. Квалификацию и текущую стадию обновляйте по факту разговора. Укажите следующий шаг, дату и ответственного. В колонку встречи вносите дату только проведённой встречи; будущая запись относится к следующему шагу. Имя, телефон и документы можно оставить в отдельном защищённом рабочем хранилище; достаточно ссылки по ID.
2. В «Платежи» каждая фактическая операция получает собственный уникальный ID и ID обращения. Сумма положительная; возврат задаётся видом операции. Обещание оплаты — «Очікується», оно не входит в подтверждённые поступления. Несколько платежей одного обращения — несколько строк, а не новый лид. Поступления минус возвраты — движение денег, не прибыль и не бухгалтерски признанная выручка.
3. В «Время» записывайте фактически затраченные часы. Продажа и исполнение требуют ID обращения. Маркетинг и управление могут быть без обращения. `TEST` и работа по тестовому обращению исключаются из сводки.
4. В «Сводка» задайте начало и конец периода. Новые обращения считаются по дате первого контакта; деньги и часы — по дате конкретной операции. Открытые стадии — текущее состояние, не исторический снимок на конец периода. Не делите деньги периода на новые лиды периода как «конверсию»: это могут быть разные когорты.

Жёлтые поля — ввод, серые — формулы. Фильтры находятся в заголовках. У каждой строки есть проверка. Повторяющиеся ID, неизвестные связи и отсутствующие обязательные суммы/даты не должны исчезать как здоровый ноль: сводка показывает число таких записей. Суммы и часы по ошибочным строкам не входят в результаты до исправления. При ошибках сводка неполная — сначала исправьте строки. Вставка из буфера может обойти проверку списка, поэтому просматривайте текстовые проверки записей.

В книге подготовлено 150 строк на каждый журнал (8–157). При выходе за 157-ю строку нужно расширить формулы, проверки и диапазоны сводки; простая дописка снизу не гарантирует включение. Пустой журнал показывает число внесённых записей 0, а не доказанный факт отсутствия клиентов. В готовой книге синтетические проверки удалены, реальные обращения не импортировались.

Храните рабочую копию с клиентскими данными локально либо в согласованном закрытом хранилище. Не добавляйте заполненную книгу в публичный Git. Общие права доступа к компьютеру эта книга не изменяет.

## Воспроизведение шаблона

`build.mjs` создаёт новую пустую книгу и выполняет проверки на временно внесённых синтетических строках. Это не импортёр и не редактор заполненной рабочей книги. Генерируйте в отдельную папку, не поверх рабочей копии.

Нужны штатный Node и `@oai/artifact-tool` из рабочего runtime Codex. Не ставьте зависимости в служебные каталоги runtime; локальная ссылка `node_modules` исключается Git. Аргумент — отдельный каталог результата:

```text
node tools/lead-desk/build.mjs <каталог_нового_шаблона>
```

Повторная запись поверх существующей книги по умолчанию запрещена. `--replace-template` предназначен только для повторной генерации известного пустого шаблона при разработке, не для заполненной рабочей копии.

Проверяются исключение TEST, ожидания и операций вне периода, отдельные возвраты, разрешённый ноль, отсутствующая сумма, повтор ID, неизвестный ID, смена границы периода, неизвестный источник, фактически проведённые встречи и последовательное заполнение следующего шага. Превью нужны для проверки вёрстки, а не для повседневного ввода. Фактический протокол выполнения и ограничения движка сохраняются рядом с результатом.
